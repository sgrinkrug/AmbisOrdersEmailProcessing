# AMBIS Receiving Drafts

## Workflow

Use the browser for AMBIS UI work and Outlook COM automation for email drafts. Do not send email.

This skill may inspect existing AMBIS attachments when deciding whether receiving instructions are due, but it has no attachment-selection or upload flow. If the user separately requests an AMBIS attachment upload, use `$ambis-find-attachment-on-disk` to locate, validate, and select each local file. That shared skill does not authorize or submit an upload; the calling attachment workflow remains responsible for authorization, duplicate checks, clicking `ADD TO REQUEST`, and verifying the resulting AMBIS record.

1. Open a visible browser panel at `https://ambis.niaid.nih.gov`.
2. If redirected to Microsoft sign-in or CAC/PIV authentication, stop and ask the user to log in manually. Do not search the web or use another site. Continue only after the user confirms login.
3. Open `Saved Searches` and select `Pending Receiving`.
4. Read the request list table for sequence, vendor, status, payment type, and other non-tag columns. Do not use the `Tags` column to decide scope, eligibility, or skip behavior.
5. For each otherwise eligible row, open the order and analyze order details, notes, and attachments to decide whether receiving instructions are due under the age rules below.
6. Stop when every listed row is excluded by non-tag order context or has packing-slip instructions that are still fresh under the age rules below.

## AMBIS Session Keepalive

During long-running AMBIS work, call the `ambis-keep-alive` skill about every 15 minutes to refresh the most recently active already-open AMBIS tab in Chrome. Track elapsed wall-clock time from the start of the AMBIS run and after each keepalive refresh. Do not open a new AMBIS tab for keepalive, and do not let keepalive submit forms, save changes, or modify AMBIS data.

## Per-Order Steps

For each eligible row:

1. Open the request and navigate to the Summary tab. Direct route navigation to `https://ambis.niaid.nih.gov/order/<SEQ>/summary` is acceptable after selecting the row or when recovering from a stale tab.
2. Extract details from the Summary page only. Wait for the page to settle before reading because AMBIS may render repeated sections slowly.
3. Open the request notes and decide whether receiving instructions are due under the packing-slip instruction age rules below.
4. If receiving instructions are not due, do not create or update a draft, do not add a note, return to the `Pending Receiving` list, and continue.
5. Create or update an Outlook draft for review only. Use `-UpdateExisting` when an existing draft with the same subject should be refreshed to the current email format.
6. Return to the AMBIS request and add a new note exactly as:

```text
Packing slip email instructions for the requester were created in Outlook. This note was generated by AI.
```

7. Verify the note appears in AMBIS.
8. Return to the `Pending Receiving` list and continue.

## AMBIS Note Control Notes

Before adding the AI-generated note, inspect existing order notes and attachments, then apply the packing-slip instruction age rules. Do not use AMBIS tags as evidence that receiving instructions were or were not sent.

Attachment inspection in this workflow is read-only. Do not open a file chooser or select a local file. Any separately authorized attachment workflow must delegate local file selection to `$ambis-find-attachment-on-disk`.

To add the note, use the Notes tab controls available on the order page. A common path is to open `Notes`, choose `NEW NOTE`, enter the note text, and click `ADD NOTE`. Keep the note plain text and one line.

## Packing-Slip Instruction Age Rules

Treat a note as packing-slip-instructions evidence when its text contains the standard phrase `Packing slip email instructions for the requester were created in Outlook`. Legacy notes from older versions of this skill that mention `AI_PACK_SLIP_REQ` may also be treated as packing-slip-instructions evidence, but only because the phrase appears in the note text, not because of any AMBIS tag value.

Determine the most recent packing-slip-instructions note by the AMBIS Notes table `DATE` column. Compare calendar dates in the local AMBIS/US Eastern date context; do not use elapsed hours. "More than 7 calendar days ago" means the most recent note date is at least 8 calendar dates before today's date.

- If no packing-slip-instructions note exists, receiving instructions are due for otherwise eligible rows.
- If the most recent packing-slip-instructions note is 7 calendar days old or newer, receiving instructions are not due.
- If the most recent packing-slip-instructions note is more than 7 calendar days old, receiving instructions are due: generate or refresh the Outlook draft and add the standard AMBIS note again.
- If the relevant note date is missing or cannot be interpreted, do not create a repeat draft or note automatically; report the order as needing manual date review.

## Extraction Rules

Use structured tables whenever available.

- Sequence number: use the request/list `SEQ`.
- Creator/Owner: use the `Routing History` table. Select the chronologically earliest non-system row where `Role` is `Requester` and `Status In` is `New request`; use the `Owner` value, falling back to `Actor`. Convert `LAST, FIRST` to `First Last`.
- End user: first look in the Justification text for `Accountable User:`. Stop the name before labels such as `User Bldg`, `Accountable User (AU)`, `Federal Supervisors`, `Supervisor`, `Servicing AO`, or `Program Custodial`. If absent, use `Ship-To Contact`. Include the end user only if different from the creator/owner.
- Vendor: prefer the request summary panel's `Vendor` value; fall back to the list row `Vendor Name`. Avoid repeated tab labels like `Justification`.
- Items: use the items table and include physical goods only. Include the AMBIS item number (`#`), description, quantity, and unit when present. Do not include line-item prices in the draft item lines.
- Exclude non-item charges whose descriptions include or equal `S/H`, `shipping`, `handling`, `tax`, `delivery`, `freight`, `postage`, `fee`, `fees`, or `contract fee`.
- Order total: retrieve the displayed `Total` / `Order Total` from the Summary panel or list `$ Total`. Do not calculate it from line items.
- Direct URL: use `https://ambis.niaid.nih.gov/order/<SEQ>/summary`.

## Email Draft Format

Create Outlook drafts only. Never send, forward, or display drafts unless the user asks.

To:
`Creator Full Name; End User Full Name` if end user is present and different, otherwise `Creator Full Name`.

Subject:
`Please confirm the receiving for AMBIS request #<SEQ>`

Body starts with `Good day,` and does not include To or Subject lines. Create an HTML Outlook draft so the package-arrival instruction line is bold:

```html
<p>Good day,</p>

<p>The order with <Vendor Name> has been placed.</p>

<p>Items ordered:<br>
<AMBIS Item #>. <Item Description> ,  <Qty> <Unit if available></p>

<p>Order Total: <Order Total></p>

<p><strong>When the package arrives, please reply to this email and include the following</strong></p>
<ol>
  <li>Packing Slip</li>
  <li>Hand-written note on the slip - "Received" or "Partially received"</li>
  <li>Receiver's signature on the slip (wet signature)</li>
  <li>Statement (in the email body) indicating what was received, i.e.</li>
</ol>

<p>Example 1: I received all items.<br>
Example 2: I received partial shipment, only line item [description] was delivered.<br>
Example 3: I received partial shipment, only 5 out of 10 items for [description] were delivered.</p>

<p><Direct AMBIS order URL></p>
```

For multiple physical items, add one numbered item line per physical item, using the AMBIS item number from the `#` column so the numbering matches the AMBIS order.

## Outlook Helper

Use `scripts/create_outlook_drafts.ps1` after extracting orders into JSON. The script creates drafts, resolves recipients, skips existing drafts with the same subject by default, and never sends. Use `-UpdateExisting` when a production rerun or stale-instructions rerun must refresh an existing draft to the current body format without creating a duplicate.

Expected JSON shape:

```json
[
  {
    "seq": "2298220",
    "to": "Rebecca Bryant; Victor Starr Kramer",
    "vendor": "Formlabs Inc.",
    "orderTotal": "$3,558.66",
    "url": "https://ambis.niaid.nih.gov/order/2298220/summary",
    "items": [
      {
        "lineNumber": "1",
        "description": "Formlab Consumables Q3 2026",
        "quantity": "1",
        "unit": "EACH"
      }
    ]
  }
]
```

Example:

```powershell
powershell -ExecutionPolicy Bypass -File "<skill>/scripts/create_outlook_drafts.ps1" -InputJson "<orders.json>"
```
